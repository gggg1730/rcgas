# 냉가스 박스 RL 매뉴얼 — 안정 착지부터 점프 플립까지

냉가스 노즐을 단 박스(차 모양)를 MuJoCo로 시뮬레이션하고, 강화학습(PPO)으로 4단계 과제를 학습시킨 프로젝트다.

| 단계 | 과제 | 한 줄 설명 | 최고 성공률 |
|---|---|---|---|
| 1 | 자세 제어 | 던져진 박스를 공중에서 수평·무회전으로 맞춰 착지 | 96% (노즐 2 N) |
| 2 | 추력 착륙 | 큰 탱크로 낙하·전진까지 죽여서 살포시 착지 | 96~100% |
| 3 | 막 던지기 | 뒤집힌 채 ±360°/s로 돌며 던져져도 착지 | 63% |
| 4 | 점프 플립 | 바닥에서 스스로 뛰어올라 공중 360° 돌고 착지 | 90% |

## 1. 설치와 실행 환경

모든 패키지는 `rl_landing/.venv` 안에 설치되어 있다 (Python 3.13, mujoco 3.x, gymnasium, stable-baselines3, PyTorch, matplotlib).

**터미널을 열 때마다 한 번:**
```
cd ~/Desktop/rcgas/rl_landing
source .venv/bin/activate
```
이후 `python ...`, `mjpython ...`으로 짧게 실행한다. 활성화하지 않았다면 `.venv/bin/python`, `.venv/bin/mjpython`을 앞에 붙인다.

- **뷰어(창이 뜨는 것)는 반드시 `mjpython`**, 나머지(학습·평가·그래프)는 `python`.
- 새로 설치할 때: `python3 -m venv .venv && .venv/bin/pip install mujoco gymnasium stable-baselines3 matplotlib`
- VS Code에서 `numpy could not be resolved` 경고가 뜨면 인터프리터를 `rl_landing/.venv/bin/python`으로 바꾸면 사라진다 (실행에는 영향 없음).
- 명령은 **코드 블록 안의 한 줄만** 복사한다. 표나 설명까지 붙여넣으면 `zsh: parse error near '|'`가 난다.

## 3. 공통 설정

### 기체
| 항목 | 값 |
|---|---|
| 물리 형상 | 박스 400 × 200 × 100 mm (보이는 차 외형은 질량·충돌 없는 장식) |
| 질량 | 1단계 2.0 kg / 2~4단계 2.8 kg (탱크 0.8 kg 포함) |
| 물리 주기 | 1 kHz (1 ms) |
| 제어 주기 | 100 Hz (정책이 10 ms마다 노즐 듀티를 정함) |
| 밸브 지연 | 15 ms (명령 후 15 ms 뒤에 실제 분사) |
| 가스 소모 | 추력 1 N당 2.6 g/s (배기속도 약 385 m/s 가정) |

### 노즐 배치 (`--layout`)
| 배치 | 구성 | 쓰는 곳 |
|---|---|---|
| (1단계 고정) | 바닥 4개(피치·롤) + 옆 4개(요), 전부 `--thrust` N | 1단계 |
| `main` | 위 8개 2 N + 바닥 중앙 메인 60 N + 앞면 제동 25 N | 2단계 |
| `roadster` | 8개뿐. 바닥 4개(마름모: 앞·뒤·좌·우) 20 N + 옆 4개 2 N | 2·3단계 |
| `wheels` | 8개뿐. 바닥 4개를 **바퀴 자리(네 모서리)** 로 20 N + 옆 4개 2 N | 2·3·4단계 |

### 정책 입력(관측)과 출력(행동)
- **입력:** 자세 회전행렬 9개 + 자이로 3개 + 높이 + 속도 (+ 과제별 추가값). 회전행렬을 써서 뒤집힌 자세도 특이점 없이 구분된다.
- **출력:** 노즐마다 0~1 듀티 (PWM 비율로 생각하면 된다).

### 공정한 비교
평가는 seed 0~299의 **똑같은 300개 던지기**로 모든 방식(무제어/방뱅/RL)을 돌린다. 뷰어는 seed 10000부터 쓴다.

## 4. 단계별 과제

### 4-1. 자세 제어 (`box_env.py`)

던진 박스를 착지 전까지 수평·정방향으로 맞춘다. 낙하 속도는 줄이지 못한다(추력이 부족).

- **던지기:** 높이 25~45 cm, 전진 3~7 m/s, 상승 1.5~3 m/s, 롤·요 ±30°, 피치 ±35°, 각 축 회전 ±120°/s
- **성공:** 착지 순간 기울기 < 5°, 회전 < 30°/s
- **보상:** 착지 기울기·정면·회전이 작을수록 +, 성공 +10, 가스 사용 −

| 노즐 추력 | 무제어 | 방뱅 | RL | RL 가스 |
|---|---|---|---|---|
| 1 N | 0% | 38% | **73%** | 2.4 g |
| 2 N | 0% | 92% | **96%** | 2.2 g (방뱅의 절반 이하) |

1 N에서 실패한 던지기는 대부분 체공이 짧은 경우다 (체공 0.7초 이상이면 97% 성공). 물리적으로 시간이 모자란 던지기가 섞여 있다.

### 4-2. 추력 착륙 (`landing_env.py`)

고압 공기 탱크(190 g)로 낙하와 전진을 죽여서 **살포시, 제자리에 가깝게** 착지한다.

- **추가 입력:** 수평 속도, 남은 가스 비율 (17개)
- **성공:** 기울기 < 5°, 회전 < 30°/s, **수직·수평 착지 속도 < 0.5 m/s**
- **보상 (최종 v3):**
  - 매 스텝 **길잡이(potential)**: 속도·기울기·회전·이동거리가 줄어든 만큼 + (LunarLander 방식)
  - 공중 체류 감점 (매 스텝 −0.02), 가스 감점
  - 착지 보너스: 성공 +10, 수평·저속일수록 +
  - **시간 초과(4초)나 2 m 이상 상승은 −30** (도망 방지)

| 배치 (일반 던지기) | 성공 | 수직 착지 속도 | 이동거리 | 가스 |
|---|---|---|---|---|
| 방뱅 (자세만) | 0% | 3.31 m/s | 3.10 m | 6 g |
| `main` (메인+제동 노즐) | **96%** | 0.14 m/s | 1.80 m | 81 g |
| `roadster` (300만 스텝) | 78% | 0.15 m/s | 2.63 m | 85 g |
| `wheels` (300만 스텝) | 25% | 0.21 m/s | 2.45 m | 74 g |
| `roadster` + 막 던지기 학습 | 99.3% | 0.36 m/s | 2.30 m | 80 g |
| `wheels` + 막 던지기 학습 | **100%** | 0.24 m/s | 2.05 m | 80 g |

- 전용 노즐이 없는 `roadster`/`wheels`는 드론처럼 **기울여서 제동**한다.
- `wheels`는 일반 던지기만 학습하면 회전 제어가 불안했지만, 막 던지기를 섞어 600만 스텝 학습하자 가장 좋아졌다.

### 4-3. 막 던지기 (`--wild`)

던지기 중 일부를 **완전 무작위 자세(뒤집힘 포함) + 각 축 ±360°/s 회전**으로 바꾼다. `--wild 0.5`면 절반.

| 모델 | 일반 던지기 | 막 던지기 |
|---|---|---|
| `wheels` + wild 0.5 | 100% | **63.3%** |
| `roadster` + wild 0.5 | 99.3% | **63.3%** |

두 배치가 막 던지기에서 똑같이 63.3%라, 나머지는 어떤 배치로도 못 살리는 (물리적으로 불가능한) 던지기일 가능성이 크다.

### 4-4. 점프 플립 (`jumpflip_env.py`)

바닥에 정지한 차가 스스로 뛰어올라 **공중에서 360° 돌고** 살포시 착지한다. 배치는 `wheels`.

- **시작:** 바닥에 수평 정지, 방향 무작위, 노즐 추력 ±10% 무작위 (실물 편차 흉내)
- **플립 판정:** 몸체 x축(롤)·y축(피치)의 누적 회전을 부호 포함 적분, 어느 한 축이 360° 넘으면 인정 (앞뒤로 흔드는 꼼수는 상쇄됨)
- **보상:** 플립 전엔 회전 진행만큼 + (한 바퀴 ≈ +19), 플립 후엔 착륙 길잡이, 착지 시 품질 보너스. 플립 없이 착지 −10, 시간 초과(5초)·이탈 −30
- **성공:** 플립 완료 + 착륙 기준(4-2와 같음)

| 결과 (300회) | 값 |
|---|---|
| 성공 / 플립 완료 | **90.3%** / 100% |
| 최고 높이 / 체공 | 0.37 m / 0.76초 |
| 착지 | 기울기 2.6°, 회전 11°/s, 수직 0.16 m/s |
| 가스 | 99 g (탱크 하나로 약 2회) |
| 플립 축 | 300회 전부 **롤(옆으로 구르기)** — 롤 관성이 피치의 약 1/3이라 가장 쉬운 길을 스스로 찾음 |

## 5-1. 게임 모드 (`game.py`)

경사로 → 단상 2개(30·60 cm) → 벽 → 목표 패드(파란 원) 코스를 직접 조종한다. 전용 창이라 `mjpython`이 아니라 `python`으로 실행한다.

| 키 | 땅 위 | 공중 |
|---|---|---|
| W / S | 가속 / 후진 | 앞 / 뒤로 기울여 이동 |
| A / D | 조향 | 좌 / 우로 기울여 이동 |
| Q / E | 제자리 회전 (요 노즐 분사) | 왼쪽 / 오른쪽 회전 |
| Space | 떠오르기 | 상승 |
| C | — | 하강 (땅에 닿으면 주행 모드) |
| L | — | **RL 자동 착지** (막 던지기 모델) |
| F | **RL 점프 옆구르기** (멈춘 상태에서) | **RL 공중 옆구르기** (0.8 m 이상) → 다시 정지 비행. 도는 중 F 한 번 더 = **더블** |
| G | **RL 점프 앞구르기** (멈춘 상태에서) | **RL 공중 앞구르기** (1.0 m 이상, 한 바퀴만) |
| X | **랜덤 던지기**: 뒤집고 돌리며 허공으로 내던짐 → RL이 받아서 착지 | 같음 |
| T / R / P | 가스 무한↔실제 190 g / 처음부터 / 일시정지 | |
| - / = | **배속** 내리기 / 올리기 (0.1 · 0.25 · 0.5 · 1 · 2배). 시작 배속은 `python game.py --speed 0.5` | |
| 1 / 2 / 3 / 4, 휠 | 카메라 추격 / 옆 / 멀리 / **운전석 1인칭**, 줌 | |
| 5, 마우스 드래그 | **자유 시점**: 왼쪽 드래그 = 차 주위로 돌리기, 오른쪽 드래그 = 시점 옮기기, 5 다시 = 차 중심으로 | |

- **자세 보조:** 공중에서 키를 놓으면 자동으로 수평이 되고, 기울여서 수평 속도를 죽인 뒤 그 자리에 떠 있다 (DJI 드론식).
- **옆 노즐로 좌우 이동:** A/D는 기울이기와 함께 옆 노즐 앞뒤 한 쌍을 같은 방향으로 쏴서 회전 없이 옆으로 민다 (최대 4 N). 키를 놓을 때 옆 미끄럼 브레이크도 거든다.
- **착지는 전부 같은 마무리:** C 착지·L(RL 착지)·X(던지기)·땅 F/G 플립·경사로 점프 모두, 땅 근처에서 어느 정도 수평이고 회전이 잦아들면 **자동 착지(AUTO TOUCHDOWN)** 가 넘겨받는다. 멈추거나 다시 올라가지 않고 계속 내려오면서 수평·감속을 함께 맞춘다 — 높을수록 빨리, 땅에 가까울수록 초당 12 cm로, 땅 근처에서 덜 맞았으면 최저 초당 4 cm까지 늦춘다 (C·L·플립 접지 0.08~0.19 m/s, 기울기 0~2°). 빨리 떨어질수록 더 높은 곳에서 넘겨받아 멈출 여유를 둔다.
- **주차 브레이크:** 땅에서 W/S를 안 누르면 걸린다 (게임용으로 차체 마찰을 낮춰 둬서 그대로 두면 미끄러짐).
- **경사로에서 날아오르면** 자세 보조만 켜진다 (가스 최소). 이때 Space로 비행, L로 RL 착지를 할 수 있다.
- **공중 플립:** 점프 플립 정책을 그대로 재사용한다. 정책은 낮은 높이에서만 돌아 봤기 때문에 1 m 이상에서는 플립을 시작하지 않는데, 플립하는 동안 높이를 0.25 m라고 알려 주면 어느 높이에서나 돈다 (시험 15/15). 한 바퀴(약 0.3초, 고도 약 0.6 m 손실) 뒤 비행 보조가 넘겨받아 1.5초 안에 다시 수평 정지 비행.
- **땅 플립은 사실 두 바퀴:** 두 플립 정책 모두 한 바퀴만 돌아도 인정되는데, 탄력으로 한 바퀴 더 돌아 수평에서 멈추는 쪽을 스스로 택했다 (회전량 중앙값 앞 701°, 옆 677°). 화면에 실제 바퀴 수가 표시된다.
- **앞구르기 학습:** 높이 조건 없이 학습하면(v1) 31 cm만 뛰어 대충 돌고 비스듬히 떨어졌다 (성공 0%). 무게중심 35 cm 이상에서만 회전을 세게 바꾸자(v2) 66 cm까지 뛰어 돌고 수평 착지 (성공 86.7%). `--flip-axis pitch --flip-min-z 0.35`
- **연속 플립 한계:** 옆구르기는 더블까지 안정(4/4). 트리플 이상은 기존 정책으로는 실패해 막아 두었다 (전용 학습 필요). 공중 앞구르기 후에는 비행 보조가 바로, 옆구르기 후에는 플립 정책이 회전을 진정시킨 뒤 넘겨받는다.
- **랜덤 던지기 범위:** 막 던지기 학습과 같은 범위(월드 +x로 3~7 m/s)로 던진다. 다른 방향으로 던지면 정책이 처음 보는 상황이라 실패가 늘었다 (7/20 → 20/30).
- **RL을 단상 위에서도 쓰기:** 높이 입력을 "바로 아래 지면까지 거리"(레이 측정)로 넣어서, 평지에서 학습한 정책이 단상 위에서도 그대로 동작한다.
- **주행은 게임용 근사:** 차체 마찰을 낮추고 구동·접지·조향을 외력으로 흉내 낸다 (실제 바퀴 물리 아님). 비행과 RL 부분은 학습 환경과 같은 물리다.
- 화면 글자는 MuJoCo 기본 글꼴이 한글을 지원하지 않아 영어로 표시된다.

## 6. 학습하기

```
python train.py --task <과제> [옵션] --out <모델이름>
```

| 옵션 | 값 | 설명 |
|---|---|---|
| `--task` | `attitude` / `landing` / `jumpflip` | 과제 (기본 attitude) |
| `--layout` | `main` / `roadster` / `wheels` | 노즐 배치 (landing·jumpflip) |
| `--wild` | 0~1 | 막 던지기 비율 (landing) |
| `--thrust` | N | 노즐 추력 (attitude) |
| `--steps` | 정수 | 학습량 (기본 200만) |
| `--out` | 이름 | 저장 이름 → `이름.zip`. **기존 모델을 덮어쓰지 않게 꼭 지정** |

예시 (이 프로젝트에서 실제로 쓴 명령):

- **로그를 파일로 남기려면** 뒤에 `> train_이름.log 2>&1`을 붙인다 (그래프용).
- 환경 8개를 병렬로 돌리며 CPU를 40~60% 쓴다. 팬 소리가 거슬리면 저전력 모드로 둬도 결과는 같다.

## 9. 개발하며 얻은 교훈

1. **착지 판정 시점:** MuJoCo는 접촉을 감지한 스텝 안에서 바로 충격력을 가한다. 그 뒤 상태로 평가하면 충돌로 생긴 회전이 섞여 성공률이 왜곡된다 (방뱅 1% → 실제 38%). **접촉 직전 상태**로 평가해야 한다.
2. **보상 기울기:** `exp(-v²)` 같은 보상은 v가 크면 거의 0이라 기울기가 없다. 3 m/s에서 감속을 전혀 못 배웠다 (v1). 멀리서도 방향을 알려 주는 항이 필요하다.
3. **보상 해킹:** 착지 감점(−13)이 시간 초과 감점(−10)보다 크자, 정책이 착지를 피해 날아올라 버텼다 (v2). **도망은 어떤 착지보다 나쁘게** 만들어야 한다.
4. **길잡이 보상(potential-based shaping):** 상태가 좋아진 만큼 매 스텝 주는 방식으로 바꾸자 바로 96% (v3).
5. **어려운 데이터가 기본 성능도 올린다:** 막 던지기를 섞어 학습하자 일반 던지기도 25% → 100% (학습량 2배와 겹친 효과라 분리 확인 필요).
6. **난수 순서:** 옵션을 추가하며 난수를 하나 더 뽑으면 "같은 300개 던지기"가 달라진다. 비교 실험에서는 주의.

## 11. 한계와 실물화 메모

시뮬레이션이 실제보다 이상적인 부분:
- 밸브가 0~1 연속 듀티로 열린다고 가정 (실제 솔레노이드는 켜짐/꺼짐뿐)
- 메인 노즐 60 N, 바닥 노즐 20 N을 지연 15 ms로 정확히 낸다고 가정
- 가스 소모로 줄어드는 질량(최대 190 g), CO₂ 냉각에 의한 추력 저하, 지면 효과 무시
- 센서가 자세·속도·높이를 오차 없이 안다고 가정

실물로 가려면: 이산 밸브 모델로 재학습, 추력·지연·질량·센서 노이즈 무작위화(도메인 랜덤화), 실측 관성 반영. 자세 추정은 **던지기 전 정지 상태에서 확정 → 비행 중 자이로 적분**(자유낙하 중 가속도계는 중력을 못 느낌). 높이는 하향 ToF, 수평 속도는 옵티컬 플로우 또는 모션캡처.

## 12. 문제 해결

| 증상 | 해결 |
|---|---|
| `zsh: parse error near '\|'` | 코드 블록의 명령 한 줄만 복사 |
| `No module named 'mujoco'` | venv 활성화 안 됨 → `source .venv/bin/activate` 또는 `.venv/bin/python` |
| 뷰어가 안 뜨거나 오류 | `python` 대신 `mjpython`으로 실행 |
| `모델.zip 없음 → RL 평가 생략` | `--model` 파일 이름 확인, 또는 먼저 학습 |
| 평가 결과가 이상하게 나쁨 | `--layout`이 학습 때와 같은지 확인 |
| 학습 중 팬 소리·발열 | 저전력 모드로 전환 (결과 동일, 시간만 늘어남) |
